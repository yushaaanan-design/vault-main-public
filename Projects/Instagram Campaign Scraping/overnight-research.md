- **Q12 learning authentication (leads, blog sources, not verified):** current advice for new projects is **Argon2id** for password hashing (OWASP's first choice), with **bcrypt at work factor 10+** still accepted and the most common in Node; store unique-salted, one-way, adaptive-cost hashes. One search result is titled "your node js authentication tutorial is wrong": read tutorials sceptically. Free study path, in order: (1) OWASP Password Storage Cheat Sheet, (2) OWASP Session Management and Authentication cheat sheets, (3) build the Gym Tracker login with bcrypt + session cookie + CSRF protection + rate limit, Claude writing and you reading every line, then a security review pass. - **Q13 skills/plugins to vet (important warning):** third-party skills and plugins run with your permissions. Reported cases: a Snyk audit of 3,984 skills on a third-party marketplace found 13.4% with a critical security issue and 76 with confirmed malicious payloads; a vulnerability in the Hookify plug-in (even in Anthropic's official marketplace) let a planted file in a repo steer the model; marketplace skills have been shown to pick dependencies (hijack risk). Practical rules: prefer Anthropic-built plugins; read every file of a third-party skill like code; treat any skill that fetches URLs as crossing a trust boundary; pin versions; never auto-install (this matches the skill-suggestions list rule). ### 14 (loop run, 2026-10-05 about 7:00 AM)
- **Q14 Telegram bot intake (leads, not tested):** with the standard Bot API a bot can **download files only up to 20 MB** (`getFile`); a typical Instagram reel is 5 to 30 MB, so many reels would fail. Fix: run a **local Telegram Bot API server** (open source, `tdlib/telegram-bot-api`), which lifts download and upload limits to about 2 GB; in python-telegram-bot local mode, `file_path` is then a local path. Simpler alternative that avoids the limit: have the bot receive **links** (not video files) and download them with `yt-dlp` on the PC. Token handling: create the bot with @BotFather and keep the token only in a local `.env` (never in chat, notes or git); restrict the bot to your own Telegram user ID. Sources: https://core.telegram.org/bots/api , https://charliemorrison.dev/blog/telegram-bot-api-file-size-limits/ , https://bigmike.help/en/devops/local-telegram-bot-api-advantages-limitations-of-the-standard-api-and-set-eb4a3b/ , https://docs.python-telegram-bot.org/en/v22.1/telegram.file.html
