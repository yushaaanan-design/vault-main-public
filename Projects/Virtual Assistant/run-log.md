## 2026-10-05 evening: Ares window behaviour fixes (for study)
Three things the user reported, with cause and fix. Files: `server.py`, `ares_window.py`, `display.html` in `C:\dev\Virtual Assistant\`.

1. **Minimize button did nothing (window popped straight back).** Cause: `_keep_on_top()` in `server.py`, run by the `keep_visible` watcher every 1.5 s, un-minimized the window every time (`ShowWindow(SW_RESTORE)`). Fix: `_keep_on_top(restore=False)` no longer restores; only an explicit `summon()` (the `Ares ...` chat command, shortcut, "show yourself") passes `restore=True`. Tested: minimized for 5 s, stayed minimized; explicit summon restored it.
2. **Cross (X) did not close it.** Cause: my earlier "always on" change made the watcher reopen the window whenever it was gone. Fix: the watcher remembers if the window was alive on the last tick (`was_alive`); if it vanished and we did not close it ourselves, that was the user's cross, so it writes `hide` into `display_pref.txt` and leaves it closed. It opens again on `ares.py show/full`, the desktop shortcut, or "show yourself". Tested by sending WM_CLOSE (what the cross sends): pref became `hide`, stayed closed 5 s later. (Why it kept closing earlier: Esc/X wrote `hide` into that same file.)
3. **Full screen -> panel closed and reopened the window.** Cause: `summon()` did `display.terminate()` then started a new process to change shape. Fix: ONE window for its whole life. `ares_window.py` now runs a small thread (`follow_pref`) that watches `display_pref.txt` (`show` = panel, `full` = full screen) and slides the same window with Win32 calls (`SetWindowPos`, 14 small steps, ease in/out, about a quarter of a second); the title bar is removed for full screen (`SetWindowLongW` without WS_CAPTION | WS_THICKFRAME) and put back for the panel. `server.py` `summon()` just writes the pref and sets `display_full`; `/display-mode` calls `summon()` so the layout flips at once. Tested: full = (0,0,1920,1080) no frame; panel = right edge 550 px wide, frame back; window handle stays the same.
- Also: a window maximized with the title-bar button used to snap back to maximized after minimize/restore; `follow_pref` now un-maximizes (`IsZoomed` -> SW_RESTORE) before every slide.
- Also today: the slim panel shows only the Central To-Do List (click a project to expand, click an item for details), plus a refresh button (see earlier row). The `Ares-behavior.md` line "comes back if it is minimized" is now out of date (minimized stays minimized); edit it if you want the rulebook to match.
- Lessons: (a) a watcher that "keeps things alive" must be able to tell the user closing something from a crash; (b) change a window's shape in place instead of restarting its process; (c) PowerShell `Add-Type` `FindWindow` returned 0 here even though the window existed; Python `ctypes` found it, so test windows from Python.
